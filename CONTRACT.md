# Core contract

Inventory scans only a root explicitly selected by the caller. Snapshots persist under app-owned Application Support, retain up to 30 observations, do not follow symlinks, and expose errors. Entry byte totals are summed file estimates: hard links, clones, directory metadata and partial coverage can make them differ from actual exclusive or reclaimable space. The volume capacity figure is separate. Directories are marked partial if any scan error occurs; absent or inaccessible content is not zero. The caller filters entries by parent for browsing and must not sum nested rows. A change is comparable only when roots and coverage are equivalent; unknown coverage is not zero. No cleanup eligibility follows from scan results.

CLI: `disk-cleanerctl request <target-available-bytes> <idempotency-key>` returns a JSON job; `status <job-id>` retrieves it and `wait <job-id>` waits. Keys are stable and unique per target. The request is persisted before acknowledgement, and a separate worker makes the capacity check. The production registry has no cleanup provider: current capacity sufficient yields completed with no action, otherwise insufficient. A failed capacity check yields failed. This cannot free space and does not authorize pnpm cleanup. Persistence failure prevents success acknowledgement. Worker launch failure marks the job failed if persistence permits. Concurrent jobs use a process lock. A queued job still unfinished after 60 seconds is marked interrupted/unknown on status retrieval; the worker cannot later start that job. No destructive work is retried. Volatile machine capacity may change after an observation.

Location growth compares matching paths, not stable object identity or usage. `largeUnchangedFiles` considers only regular file modification dates; a directory's own modification time does not establish that its descendants are unchanged. An observation-limit error marks the snapshot incomplete and suppresses comparisons.
